# WorkHere Project Rules

## Workflow

- Общаемся на русском.
- Работаем шаг за шагом.
- Перед любым созданием, изменением или удалением файлов сначала описывать, что именно будет изменено, и ждать явного подтверждения.
- Сначала делаем desktop-версию. Адаптив выполняется отдельным этапом.
- PixelPerfect проверяем через Figma и браузерное сравнение.
- Каждый новый крупный блок реализуется в 3 этапа: скелет, наполнение, PixelPerfect.

## Stack

- Проект: Vanilla Vite.
- Разметка: HTML.
- Стили: SCSS + БЭМ.
- Интерактив: vanilla JS.
- Слайдеры: Swiper, если слайдер явно нужен по дизайну.

## HTML

- Новые крупные секции добавлять как page-wrapper + отдельный БЭМ-блок внутри.
- Пример структуры:

```html
<section class="page__block-name">
  <div class="block-name">
    ...
  </div>
</section>
```

- Page-wrapper отвечает за внешний контекст секции: фон, внешние отступы, ограничение ширины, если это относится к секции.
- Внутренний БЭМ-блок отвечает за собственную композицию и элементы.
- Не создавать отдельный БЭМ-блок, если достаточно элемента текущего блока.

## SCSS And BEM

- Один БЭМ-блок = один SCSS-файл.
- Имя файла блока: `src/scss/blocks/_block-name.scss`.
- Подключение блока выполняется в `src/scss/main.scss`.
- Стили писать вложенно от корневого блока:

```scss
.block {
  &__element {
  }

  &--modifier {
  }
}
```

- Не писать элементы отдельно от блока:

```scss
// Не используем
.block__element {
}
```

- Внешние отступы задаются родительскими элементами или page-wrapper, не самим БЭМ-блоком.
- Блок не должен сам задавать внешний `margin`.
- `padding` секции задается на `page__...` wrapper, если это внешний отступ секции.
- Жесткие ограничения по высоте (`height`, `min-height`) задавать только в исключительных случаях:
  - Figma явно задает высоту секции;
  - sticky/scroll animation требует фиксированной сцены;
  - элемент имеет фиксированный формат, например кнопка, аватар, карточка, слайдерная область.
- Если высота нужна только для отступов или композиции, сначала использовать padding, content flow, aspect-ratio, max-width.
- Фон секции задает page-wrapper или общий wrapper. Внутренний блок получает фон только если фон принадлежит самому компоненту.

## JavaScript

- Каждый самостоятельный интерактив выносить в отдельный модуль `src/js/*.js`.
- Модуль экспортирует init-функцию вида `initBlockName()`.
- `src/main.js` только импортирует init-функции и вызывает их.
- Не превращать `main.js` в файл с логикой.
- JS для scroll-анимаций должен работать через CSS custom properties, если это уже принято в блоке.

## Assets

- Figma assets складывать по блокам:

```text
src/assets/figma/<block-name>/
```

- Повторяемые UI assets складывать в общий каталог:

```text
src/assets/figma/ui/
```

- Растровые изображения по возможности хранить в `.webp`.
- Иконки, стрелки, декоративные векторные элементы хранить в `.svg`.
- Для изображений указывать `width`, `height`, `alt`.
- Декоративным изображениям задавать пустой `alt=""` и при необходимости `aria-hidden="true"`.

## Forms And Interactions

- Формы валидируются локально, без backend-отправки, пока backend не задан.
- Ошибка обязательного поля: `* Заполните обязательное поле`.
- Hover-состояния брать из Figma-фрейма hover effects.
- Если hover-состояние для элемента есть в Figma, не придумывать альтернативное без согласования.

## Current Project Patterns

- `feature-section` использует общий механизм scroll-progress через `data-progress`.
- `feature-panel` отвечает за внутренний контент вкладки и brush background.
- `ai-stage` использует JS-таймлайн и CSS variables для анимаций.
- `workhere-ai` использует отдельный JS-модуль для scroll-driven анимации.
- `reviews` использует Swiper и отдельный модуль `reviews-slider.js`.
